## 1. 한 줄 요약

**종이책 페이지를 찍으면 형광펜이 글자 줄에 딱 붙어 그어지고, 그 결과를 인스타 스토리에 바로 올리며, 올린 구절은 책별로 쌓이는 앱.**
프로토타입이 답할 질문은 딱 하나다. **"이 형광펜이 인스타 스토리 편집기보다 확실히 나은가?"** 아니면 종료한다.

## 2. 왜 이 순서인가

스코어카드 v2의 가장 약한 곳은 원가·운영이 아니라 **문제 강도(4점)와 무료 대체재 대비 우위**다. 인스타 스토리 편집기에 이미 형광펜·스티커·GIF가 있다(High). 그래서 프로토타입은 기능을 늘리는 순서가 아니라 **가장 싸게 죽일 수 있는 가정부터** 재는 순서로 짠다.

| 순서 | 가정 | 틀리면 |
|---|---|---|
| ① | 휘어진 종이 페이지에서도 한글 줄을 온디바이스 OCR로 안정적으로 잡을 수 있다 | 줄 스냅이 성립하지 않는다 → 자유 드로잉 보정으로 후퇴하거나 종료 |
| ② | 같은 구절을 만들면 사람들이 인스타 편집기 결과물보다 이 앱 결과물을 고른다 | **종료** (스코어카드 출구 기준 1) |
| ③ | 꾸민 결과물을 실제로 공유하고, 공유가 신규 설치를 부른다 | 10만 도달 경로 없음 → 아카이브 전용 축소 여부를 사용자가 결정 |
| ④ | 아카이브가 다시 열어볼 이유가 된다 (W4 리텐션) | 도구로만 쓰고 떠난다 → 1회성 유틸 |

피드·구절 답글·책별 채널·DM은 ③까지 통과한 뒤의 2단계다. 이번 프로토타입에는 넣지 않는다.

## 3. 대상 사용자

| 구분 | 정의 | 모집 경로 (프로토타입) |
|---|---|---|
| 1차 | 인스타에 독서 게시물·스토리를 올려 본 20~30대 | #책스타그램·#필사 게시 계정에 DM 모집, 독서 모임 오픈채팅 |
| 2차 | "올리고 싶었는데 꾸미기가 귀찮아서 안 올렸다"는 사람 | 1차 모집 시 스크리너 질문으로 구분해 따로 집계 |

- 월간 인스타 독서 피드 게시 계정은 2~6만(실측, Medium)이다. 10만을 채우려면 스토리 게시자와 2차 집단이 필요하다. 그래서 **2차 집단의 공유 전환율을 따로 본다.**
- 만 14세 미만은 모집하지 않는다. 앱에 가입이 없으므로 법정대리인 동의 절차도 필요 없다.

## 4. 핵심 사용자 흐름

```
[카메라/앨범] → [줄 인식 (온디바이스, <1초)] → [손가락으로 문지르기 → 형광펜이 줄에 스냅]
      → [스타일: 형광펜 3종 · 밑줄 · 포커스 모드 · 스티커] → [미리보기 9:16]
      → [인스타 스토리로 공유] / [이미지 저장]
      → [어느 책인가? ISBN 바코드 스캔 or 최근 책 선택] → [내 책장에 구절 저장]
```

- 공유하기 전에 책을 묻지 않는다. **공유까지 걸리는 탭 수가 인스타 편집기보다 많으면 진다.** 책 지정은 공유한 뒤에 한 번만 묻고, 건너뛸 수 있다.
- 목표 소요 시간: 사진 촬영부터 공유 시트까지 **중앙값 30초 이내**. P1 비교 테스트에서 인스타 편집기와 같이 잰다.

### 5.2 줄 스냅 알고리즘 (F2·F3)

1. OCR 결과에서 줄(line) → 단어(element) 박스를 얻는다. 네 꼭짓점 좌표를 쓴다.
2. 줄마다 단어 박스 하단 중점을 이은 **기준선 폴리라인**을 만든다. 휘어진 페이지는 이 폴리라인이 곡선을 따라간다.
3. 터치 궤적의 각 점을 가장 가까운 기준선에 투영한다. 궤적이 줄 높이의 60% 이상 벗어나면 다음 줄로 넘어간 것으로 본다.
4. 선택 구간은 **단어 경계로 스냅**한다(글자 중간에서 끊기지 않게).
5. 형광펜은 해당 단어 박스들의 합집합 영역을 약간 부풀린 뒤 질감 텍스처로 칠한다. 밑줄은 기준선 폴리라인을 약간 떨리게 그린다.
6. **실패 시 폴백:** 인식된 줄이 없는 영역에서는 자유 드로잉으로 전환하고, 직선에 가까우면 보정한다. 폴백이 쓰인 비율을 계측한다.

## 6. 기술 구성 (1인, 기성 부품만)

| 층 | 선택 | 이유 · 확인할 것 |
|---|---|---|
| 앱 | **Flutter** | 한 코드베이스로 iOS 먼저, Android는 P1 통과 후. 캔버스 렌더링과 제스처가 강하다 |
| OCR | **Google ML Kit Text Recognition v2 (Korean)** — `google_mlkit_text_recognition` | iOS·Android 모두 온디바이스, 무료, 줄·단어 박스와 꼭짓점 좌표를 준다. 비교 대상: iOS Vision `VNRecognizeTextRequest`(한국어 지원). **P0에서 두 엔진을 같은 테스트셋으로 비교해 정한다** |
| 바코드 | ML Kit Barcode Scanning (EAN-13 = ISBN) | 온디바이스, 무료 |
| 렌더링 | Flutter `CustomPainter` + blend mode multiply, 이미지 합성은 `dart:ui` | 애니메이션 MP4는 프레임 렌더 → iOS `AVAssetWriter` 플랫폼 채널 (P2) |
| 로컬 저장 | SQLite (`drift`) + 원본 사진은 앱 문서 폴더 | 서버 저장 없음 |
| 인스타 공유 | iOS: `instagram-stories://share` + 페이스트보드. **Facebook App ID 등록 필요** `[검증 필요 — P0 1일차에 확인]` / 폴백: 시스템 공유 시트 | Android는 `com.instagram.share.ADD_TO_STORY` 인텐트 |
| 도서 메타 | 알라딘 Open API (TTB 키) → Cloudflare Worker 프록시 + KV 캐시(ISBN 키, 영구) | 키를 앱에 넣지 않는다. 일 호출 한도·출처 표기 조건 `[검증 필요]`. 폴백: 국립중앙도서관 ISBN API |
| 짧은 링크 | Cloudflare Worker (무료 티어) | 클릭 로그만 남기고 스토어로 리디렉트. Firebase Dynamic Links는 2025년에 종료됐다 `[Knowledge-Based — 검증 필요]` |
| 계측 | PostHog Cloud (무료 티어 월 100만 이벤트) `[검증 필요]` | 익명 기기 ID. 개인정보는 수집하지 않는다 |
| 배포 | P1: TestFlight 외부 테스트 / P2: App Store 공개 | 공유→설치 측정에는 공개 출시가 필요하다 |

- **iOS 먼저인 이유:** 국내 20대의 아이폰 비중이 절반을 넘는다 `[Knowledge-Based — 검증 필요, 한국갤럽 스마트폰 사용률 조사로 확인]`. 인스타 스토리 공유 경로도 iOS 쪽이 문서화가 잘 돼 있다.
- 쓰지 않는 것: 웹/PWA. 브라우저 Tesseract.js는 한글 줄 박스 품질이 낮고, 카메라·공유 경험에서 인스타 편집기를 이길 수 없다(v1 계획을 폐기하는 이유).

## 7. 계측 설계

### 7.1 이벤트

| 이벤트 | 속성 | 어느 지표로 가나 |
|---|---|---|
| `photo_loaded` | 출처(카메라/앨범), OCR 소요 ms, 인식 줄 수 | 성능 |
| `highlight_made` | 스냅/폴백, 선택 줄 수, 되돌리기 횟수 | 스냅 품질 |
| `export_started` / `export_done` | 형식(이미지/MP4), 스티커 수, 포커스 모드 on/off | 공유 전환 |
| `share_target` | 인스타 스토리 / 저장 / 기타 | 공유 전환 |
| `book_linked` | ISBN 스캔 / 기존 책 / 건너뜀 | 아카이브 |
| `archive_opened` | 세션 내 첫 화면 여부 | 리텐션 원인 |
| `fakedoor_tap` / `fakedoor_notify` | 팩 ID | RPU 가정 |
| `install_source` | 첫 실행 응답(스토리에서 봄/지인/검색/기타) | 확산 |
| 링크 클릭 (서버) | 책코드, 시각 | 확산 |

### 7.2 지표와 판정선 (스코어카드 v2 출구 기준 그대로)

| # | 지표 | 계산식 | 판정선 | 미달 시 |
|---|---|---|---|---|
| 1 | **대체재 우위** | 앱 결과물 선택 수 ÷ 비교 참가자 수 (§8) | **≥ 60%, 95% 신뢰구간 하한 > 50%** | **종료** |
| 2 | 공유 전환 | `share_target=인스타` 세션 ÷ `highlight_made` 세션 | ≥ 40% | 흐름 단순화 후 1회 재측정 |
| 3 | 확산 | (링크 클릭 → 설치 + `install_source=스토리`) ÷ 인스타 공유 수 | ≥ 0.05 | 아카이브 전용 축소 여부를 사용자가 결정 |
| 4 | 리텐션 | W4 활성 ÷ 코호트 설치 | ≥ 15% (기준선은 P2 착수 전 확인) | 아카이브 가치 재설계 |
| 5 | 실측 CPU_월 | 월 서버비 ÷ MAU | ≤ 20원 | 캐시·샘플링 |

- 확산 지표는 정확히 잴 수 없다. iOS는 링크 → 설치 귀속이 막혀 있다. 그래서 **링크 클릭(하한)과 자기 보고(상한) 두 값을 같이 적는다.**
- 1번 판정선에 신뢰구간 조건을 붙인 이유: 표본 30명에서 60%면 95% 구간이 약 42~78%라 아무것도 말해 주지 않는다. **하한 50%를 넘기려면 약 100명**이 필요하다. 100명을 못 모으면 결과를 "방향성"으로만 적고 종료·진행을 확정하지 않는다.

## 8. 비교 테스트 프로토콜 (P1, 판정선 1번)

1. 참가자는 **자기 책**에서 고른 구절 1개를 쓴다. 우리가 고른 페이지를 쓰면 동기가 사라진다.
2. 같은 구절로 두 결과물을 만든다.
   - (A) 인스타 스토리 편집기
   - (B) 이 앱
   - 순서는 반씩 바꾼다(카운터밸런싱).
3. 만든 두 장을 나란히 놓고 **"실제로 스토리에 올린다면 어느 쪽?"** 을 고르게 한다. 의견을 묻지 않고 선택을 받는다(Mom Test).
4. 각각의 제작 시간을 화면 녹화나 앱 타이머로 잰다.
5. 원격 비대면으로 진행한다: TestFlight 초대 → 구글 폼에 두 이미지와 선택을 제출. 1인 운영 부하는 모집 DM과 폼 확인뿐이다.
6. **보조 판정:** 선택과 별개로, 참가자가 7일 안에 실제로 앱 결과물을 스토리에 올렸는지 본다(`share_target`). 말보다 행동이 우선이다.
7. 인터뷰는 이 테스트 뒤에, 이탈자를 포함해 5건 이상 한다(`discovery/interview-guide.md`를 v2 기준으로 고쳐 쓴다).

### 10.2 10만 MAU 외삽 (CPU_월)

서버에 사진을 올리지 않으므로 v2 브리프의 R2 스토리지 항목도 빠진다.

- 도서 메타: 신규 ISBN 조회 월 약 2만 건. KV 읽기·쓰기는 Workers 유료 $5 구간에 포함 → 약 0.07원/인 `[Assumption]`
- 짧은 링크: 공유 1인 월 4건 × 클릭 → Workers 요청 월 수십만 건. 같은 $5 구간
- 계측: 1인 월 150 이벤트 × 10만 = 1,500만 이벤트. **이게 가장 큰 변동비다.** 무료 100만 초과분에 대해 10% 샘플링을 하면 무료 구간 근처에 머문다 `[Assumption, PostHog 단가 검증 필요]`
- **CPU_월 ≈ 0.1~1원** (녹색). 서버 UGC가 생기는 2단계(피드)에서 v2 브리프의 5~10원으로 올라간다.
- **P2 공개 출시 후 실측으로 교체한다**(판정선 5번).

## 11. 운영 부하 (조건 3)

| 항목 | 프로토타입 | 이유 |

| 가입·탈퇴 | 없음 | 계정이 없다 |
