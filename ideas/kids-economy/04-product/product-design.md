# 제품 설계 — kids-economy

작성일: 2026-09-17 · 단계: S3 준비 (POC 범위 정의 전 단계)
전제: 만 6~9세 자녀를 둔 **부모**가 사용자 · 아이 계정 없음(COPPA) · 현금 기반 · 실물 세 칸 지갑 + 앱

---

## 0. 설계를 가르는 결정 하나

> **건별 지출 기록을 하지 않는다.**

용돈기입장은 세 가지 이유로 우리 제품이 아니다.

| 이유 | 근거 |
|---|---|
| 무료로 포화된 축이다 | 한국은행이 양식을 배포하고, 부지런·개인 개발 앱이 전부 무료다. 여기 들어가면 Kill Rule 5에 걸린다 |
| 입력 부담이 A1을 죽인다 | 가장 위험한 가정이 "부모가 주 1회 입력을 4주 이상 지속한다"인데, 건별 기록은 주 10~13회 입력이다 |
| 현금이라 어차피 정확할 수 없다 | 문구점에서 900원 쓴 걸 부모가 알 방법이 없다 |

**대신 주 1회 "세어보기"를 한다.** 아이가 지갑을 열어 남은 돈을 세고, 부모가 숫자 셋을 입력한다. 30초다.
정확도는 떨어지지만 **아이가 자기 돈을 직접 세는 행위 자체가 학습**이고, 우리가 필요한 데이터는 건별 내역이 아니라 **봉투별 잔액 추이**다.

---

## 1. 앱의 정체

> **앱은 교육 콘텐츠가 아니다. 부모를 위한 리마인더 + 대화 스크립트 + 기록이다.**

학습은 화면이 아니라 **지갑과 대화에서** 일어난다. 앱은 그 오프라인 행동을 **촉발하고 남긴다.**

| 장면 | 오프라인에서 일어나는 것 | 앱이 하는 것 |
|---|---|---|
| S1 나누기 | 아이가 지갑 세 칸에 실제 돈을 넣는다 | 배분일을 알리고, 비율을 제안하고, 결과를 남긴다 |
| S2 멈추기 | 아이가 하루를 기다리고 다시 생각한다 | 타이머를 돌리고, 질문 한 줄을 주고, 만료를 알린다 |
| S5 돌아보기 | 부모와 아이가 5분 이야기한다 | 세 줄 요약과 질문 세 개를 띄운다 |

### 아이는 무엇을 보나 — 계정이 아니라 **넘겨주기 모드**

아이 계정을 만들지 않는다(COPPA·데이터 최소화). 대신 **부모가 자기 폰을 잠깐 아이에게 넘기는 화면**을 만든다.

- 로그인 없음, 세션 없음, 아이 데이터 수집 없음
- 큰 글씨, 그림 위주, 버튼 두세 개
- 부모가 "아이에게 보여주기"를 누르면 진입, 완료하면 부모 화면으로 복귀

## 2. 화면 목록

### 온보딩 (첫 실행, 4화면)

| # | 화면 | 내용 |
|---|---|---|
| O1 | 아이 정보 | **닉네임과 나이만.** 실명·생년월일·사진 받지 않는다 (COPPA 방어선) |
| O2 | 용돈 설정 | 금액 + 주기(주/격주/월). 기본값 = 나이별 제안치 |
| O3 | 세 칸 비율 | 기본 제안 **쓸 돈 50 / 모을 돈 40 / 나눌 돈 10**. 부모가 조정 가능. "비율은 아이가 정하게 하는 게 좋아요" 한 줄 |
| O4 | 지갑 준비 | ① 도안 PDF 내려받기 ② 집에 있는 걸로 하기(봉투·통 3개) ③ 이미 3칸 지갑이 있어요 |

> O4가 이 제품의 **첫 번째 관문**이다. 여기서 이탈하면 S1이 성립하지 않는다.

### 상시 화면

| # | 화면 | 핵심 요소 |
|---|---|---|
| **H** | **홈** | 세 봉투(잔액) · 대기 중인 물건 · 다음 할 일(배분일 D-n / 주말 돌아보기) · 목표 진행률 |
| **A** | **배분하기** (주 1회) | 이번 주 금액 확인 → 세 칸 나누기(슬라이더 또는 프리셋) → **넘겨주기 모드**로 아이가 직접 |
| **W1** | **갖고 싶은 것 담기** | 이름 + 가격 + (선택)사진 → **질문 한 줄: "이걸 사면 못 사는 건 뭐야?"** → 아이 답 입력 → 타이머 시작 |
| **W2** | **결정하기** (대기 만료 시) | "어제 담은 〈포켓몬 카드〉, 아직도 갖고 싶어?" → **[산다] [지운다]**. 지우면 그 금액이 모을 돈으로 이동하고 목표까지 남은 거리가 줄어드는 게 **그 자리에서** 보인다 |
| **C** | **세어보기** (주 1회, 30초) | 세 칸에 얼마 남았는지 숫자 셋 입력. 아이가 세고 부모가 적는다 |
| **R** | **주말 돌아보기** | 세 줄 요약 → 질문 3개(잘한 것/아쉬운 것/다음 주 바꿀 것) → **넘겨주기 모드** |
| **G** | **목표** | 모을 돈의 목적. 이름·금액·진행률·예상 달성 시점 |
| **S** | **설정** | 용돈 금액·주기, 대기 시간, 알림, 도안 다시 받기 |

### 넘겨주기 모드 (아이용 3화면)

| # | 화면 | 아이가 하는 일 |
|---|---|---|
| K1 | 나누기 | 동전 그림을 세 칸에 끌어 넣는다. 숫자보다 **크기와 색**으로 보여준다 |
| K2 | 기다리기 | 담아둔 물건과 남은 시간. "내일 아침에 다시 물어볼게" |
| K3 | 돌아보기 | 질문 하나씩, 큰 글씨. 말로 답하면 부모가 받아적는다 |

## 3. 화면 흐름

```
 [온보딩 O1→O4] ──▶ [홈 H]
                      │
   ┌──────────────────┼──────────────────┬─────────────────┐
   │ 배분일 알림       │ 아이가 뭘 갖고    │ 주말 알림        │ 주 1회
   ▼                  │ 싶다고 말함       ▼                 ▼
 [배분 A]             ▼                [돌아보기 R]      [세어보기 C]
   │              [담기 W1]                │                 │
   ▼                  │                    ▼                 │
 (넘겨주기 K1)         │ 타이머 시작      (넘겨주기 K3)        │
   │                  ▼                    │                 │
   └───────────▶ ⏳ 대기 ──알림──▶ [결정 W2] ──┴─────────────┘
                                      │
                         ┌────────────┴────────────┐
                      [산다]                    [지운다]
                         │                          │
                    쓸 돈 차감              모을 돈 +금액 → [목표 G] 진행
```

## 4. 대기 규칙 (S2 상세)

저학년은 규칙이 **하나**여야 한다. 둘부터는 부모가 대신 관리하게 되고, 그게 JTBD가 피하려던 잔소리다.

| 항목 | 값 | 근거 |
|---|---|---|
| 기본 대기 | **하룻밤 (다음 날 아침 9시까지)** | 저학년 주 용돈 3,750~10,000원 규모에서 대부분의 구매가 소액. "하루 자고 정하기"가 아이가 기억할 수 있는 유일한 규칙 |
| 예외 | 목돈(세뱃돈 등)으로 사는 3만원 이상 → **7일** | 판단 빈도가 낮아 규칙이 둘이어도 감당 가능 |
| 부모 우회 | 가능하되 **기록에 남는다** ("기다리지 않고 샀어요" 버튼) | 우회를 막으면 앱을 안 쓴다. 대신 A2 검증 데이터가 된다 |

**북극성 지표: 대기 후 취소율.** 이 숫자 하나가 제품이 작동하는지를 말한다.

## 5. 알림 — 전부 네 종류

입력 부담(A1)만큼이나 알림 피로가 이탈을 만든다. 넷을 넘기지 않는다.

| 알림 | 빈도 | 문구 예시 |
|---|---|---|
| 배분일 | 주 1회 | "용돈 주는 날이에요. 셋으로 나눠볼까요?" |
| 대기 만료 | 건별 | "어제 담은 〈포켓몬 카드〉, 아직도 갖고 싶은지 물어보세요" |
| 주말 돌아보기 | 주 1회 | "이번 주 5분만. 질문 세 개 준비해뒀어요" |
| 목표 달성 | 드묾 | "목표를 채웠어요. 같이 사러 갈 시간이에요" |

세어보기(C)는 별도 알림 없이 **배분일 화면에 붙인다** — 어차피 같은 날 지갑을 연다.

## 6. 데이터 모델 (최소)

```
Parent      : id, email, locale, timezone, pushToken
Child       : id, parentId, nickname, ageBand        ← 실명·생년월일 없음
Allowance   : childId, amount, currency, period, nextPayoutAt
Bucket      : childId, type(spend|save|share), ratio, balance
Week        : childId, weekOf, allocated{3}, counted{3}, countedAt
WishItem    : id, childId, name, price, photoUrl?, createdAt,
              expiresAt, status(waiting|bought|dropped|skipped),
              tradeoffAnswer                          ← "못 사는 건 뭐야" 답
Goal        : childId, name, targetAmount, currentAmount
Reflection  : childId, weekOf, best, regret, changeNext
```

**아이 개인정보는 닉네임과 연령대뿐이다.** 사진은 위시 아이템(물건)에만 붙고 아이 얼굴은 받지 않는다.

## 7. UX 원칙 다섯

| # | 원칙 | 왜 |
|---|---|---|
| 1 | **부모 조작은 주 1회 60초 이내** | A1이 가장 위험한 가정이다. 입력 시간이 곧 이탈률 |
| 2 | **아이 화면은 모드지 계정이 아니다** | COPPA·데이터 최소화. 규제와 제품이 같은 방향 |
| 3 | **숫자보다 크기와 색** | 6~9세는 3,750원과 1,200원의 차이를 숫자로 못 느낀다. 봉투 크기로 보여준다 |
| 4 | **앱이 가르치지 않는다. 부모가 물어볼 질문을 준다** | 효과가 확인된 조건은 "어른이 트레이드오프를 말로 설명한 경우"뿐이었다 |
| 5 | **참는 것이 진전으로 보여야 한다** | 취소한 금액이 목표 진행률을 밀어 올리는 장면이 그 자리에서 보인다 |

## 8. 의도적으로 넣지 않는 것

| 뺀 것 | 이유 |
|---|---|
| 건별 지출 기록·영수증 촬영 | §0 |
| 금융 퀴즈·레벨·뱃지·수료증 | 지식 +0.25 SD / 행동 +0.05 SD. 측정하기 쉬워 목표가 되기 쉽고 그래서 위험 |
| 집안일·미션 연동 보상 | 저축률을 낮춘다. 부지런이 정확히 이 구조다 |
| 카드 발급·충전·자동이체 | 규제·정산·분쟁이 따라오고, **카드가 있으면 대기 기능을 만들 동기가 사라진다** |
| 조르기·용돈 추가 요청 | 예산 제약 자체를 지운다 |
| 또래 랭킹·공유 피드 | 소비가 사회적 비교에 붙으면 필요/욕구 구분이 무너진다 |
| 주식·투자 체험 | 6~10세 역량에 "투자는 저축과 다르다" 한 줄뿐 |

## 9. POC 범위 (1인 12주) — 예비안

| 주차 | 범위 |
|---|---|
| 1–2 | 데이터 모델 · 인증 · 온보딩 O1~O4 |
| 3–5 | 홈 H · 배분 A · 세어보기 C · 넘겨주기 K1 |
| 6–8 | 담기 W1 · 대기 타이머 · 결정 W2 · 알림 4종 |
| 9–10 | 돌아보기 R · 넘겨주기 K3 · 목표 G |
| 11 | 도안 PDF · 설정 · 영문 문구 |
| 12 | 계측(실측 CPU·운영 부하) · 베타 배포 |

**12주에 못 넣는 것:** 지갑 실물(W-B), 고학년 장면(S3·S4·S6), 영국·EU 출시, 결제·구독.
구독 결제는 POC 이후다 — 먼저 **A1(부모가 4주 지속하는가)**을 보고, 그게 서지 않으면 과금 논의는 의미가 없다.
