# POC 범위 — kids-economy

작성일: 2026-09-17 · 단계: S3 · 제약: **1인 · 12주 · 기성 부품만**
검증 목표: **가정 A1 — 부모가 주 1회 5분 입력·대화를 4주 이상 지속하는가**

---

## 0. 가장 비싼 실수를 먼저 막는다

기본 계획은 "8주 개발 → 4주 관찰"이었다. 그러면 **A1이 깨졌을 때 12주를 이미 쓴 뒤에 안다.**

A1의 핵심은 앱 기능이 아니다. **부모가 매주 5분을 낼 의향이 있는가**다. 그건 앱 없이 잴 수 있다.

```
Phase 0  수동 검증 (Wizard of Oz)     2~3주   ← A1이 여기서 깨지면 끝. 비용 3주
   ↓ 통과해야만
Phase 1  앱 개발                      7~8주
   ↓
Phase 2  실사용 계측                  2~3주
```

**실패 비용이 12주에서 3주로 줄어든다.** 이 모델에서 가장 싼 검증은 산수였고, 그 다음으로 싼 검증이 이것이다.

---

## Phase 0 — 수동 검증 (2~3주)

앱을 만들지 않는다. **메신저와 PDF 한 장으로 주간 루프를 사람이 돌린다.**

| 항목 | 내용 |
|---|---|
| 참가 | **10~15가구** (만 6~9세 자녀, 이미 용돈을 주는 집) |
| 준비물 | 지갑 두 칸 도안 PDF(A4 1장) + 개별 메신저 대화방 |
| 월요일 | "용돈 주는 날이에요. 두 칸에 나눠보고 사진 한 장 주세요" |
| 상시 | "갖고 싶은 게 생기면 알려주세요" → 운영자가 수동으로 다음 날 아침 리마인드 |
| 주말 | 질문 3개를 그대로 보냄. 부모가 아이 말을 받아 적어 답장 |
| 운영자 | **사람이 전부 수동 처리.** 자동화는 Phase 1의 일이다 |

### 측정 (A1의 대리 지표)

| 지표 | 무엇을 말하나 | 통과선 |
|---|---|---|
| **4주 지속률** | A1 그 자체 | **50% 이상** (10가구 중 5가구가 4주차 응답) |
| 주간 응답 시간 | 5분 설계가 현실적인가 | 중앙값 10분 이내 |
| 3주 연속 무응답 시점 | 언제 빠지는가 | 2주차 집단 이탈이면 온보딩 문제 |
| **지갑 준비율** | 온보딩 첫 관문 통과율의 대리치 | **60% 이상** |
| 담긴 물건의 소비재/지속재 분포 | 규칙 D 검증 (A2-a) | 과자가 거의 안 담히면 가설 확인 |
| 대기 후 취소율 | 북극성 지표의 첫 관측 | 숫자 자체보다 **0이 아닌지** |

### Phase 0에서 죽는 조건

- 4주 지속률 **30% 미만** → A1 반증. **종료한다.** 앱을 만들어도 같은 사람들이 같은 이유로 빠진다
- 지갑 준비율 **40% 미만** → 온보딩 관문이 너무 높다. 실물 요구를 재설계하고 Phase 0을 다시 돌린다

> **주의:** Phase 0의 지속률은 **과대평가된다.** 사람이 직접 챙기고 참가자가 아는 사람일 가능성이 높다. 그래서 통과선을 50%로 높게 잡았다 — 여기서 50%가 안 나오면 익명 앱 사용자에게서는 훨씬 낮다.

### 덤: 모집 자체가 채널 실험이다

10~15가구를 어디서 모으는지가 **초기 채널의 축소판 테스트**다. 맘카페·지인·커뮤니티 중 어디서 몇 명이 왔는지 기록한다. G2 조건 2(초기 시드 경로)의 첫 데이터가 된다.

## Phase 1 — 앱 개발 (7~8주)

Phase 0 통과 시에만 착수한다.

| 주차 | 범위 |
|---|---|
| 1–2 | 데이터 모델 · 부모 인증 · 온보딩 O1~O4 (도안 다운로드 포함) |
| 3–4 | 홈 H · 배분 A · 세어보기 C |
| 5–6 | 담기 W1(소비재/지속재 분류) · 대기 타이머 · 결정 W2 · 안 산 뒤 미리보기 |
| 7 | 돌아보기 R · 목표 G · 알림 4종 |
| 8 | 계측 심기 · 설정 · 베타 배포 |

### 들어가는 것

화면 9개 — 온보딩 4, 홈, 배분, 담기, 결정, 돌아보기. 여기에 목표·세어보기·설정이 최소 형태로.

### 뺀 것 (그리고 왜)

| 뺀 것 | 이유 | 언제 |
|---|---|---|
| **넘겨주기 모드 K1·K3** | 아이 화면은 A1 검증에 필요 없다. 부모 지속이 먼저다 | Phase 2에서 A/B로 |
| **영문판** | 국내 POC로 결정. 과금 검증 때 필요 | 리텐션이 선 뒤 |
| **결제·구독** | A1이 서기 전에 과금을 논할 이유가 없다 | POC 이후 |
| 고학년 장면 S3·S4·S6 | 저학년 진입점에 집중 | 코호트 확장 시 |
| 실물 지갑 W-B | 도안(W-A)으로 충분. 측정 전에 만들면 매몰비용이 판정을 기울인다 | A4 측정 후 |
| 사진 첨부 | 스토리지·모더레이션이 붙는다 | 필요가 확인되면 |
| 소셜·공유 | 또래 비교는 설계상 배제 항목 | 안 만든다 |

### 기성 부품만 쓴다 (원가 설계와 일치)

- 인증·DB: 서버리스 Postgres 또는 관리형 BaaS 무료 티어
- 알림: FCM
- **생성형 모델 호출 없음.** 주간 요약도 Phase 1에서는 규칙 기반 템플릿. 월 1회 배치 요약은 Phase 2 이후
- 도안 PDF: 정적 파일

## Phase 2 — 실사용 계측 (2~3주)

**추정 CPU를 실측 CPU로, 추정 운영 부하를 실측으로 바꾸는 것이 이 단계의 절반이다.**

| 실측할 값 | 지금 값 | 왜 중요한가 |
|---|---|---|
| **온보딩 통과율** | 추정 30~70% | 획득 산수의 첫 칸. 중간 시나리오(12%) 미달이면 종료 |
| **M1 활성률** | 추정 20~60% | 두 번째 칸 |
| **DB 쿼리 비용** | 추정 월 84만원(100만 기준) | 원가 모델에서 가장 불확실한 항목. 2배 이상 틀릴 수 있다 |
| 가구당 API 호출 수 | 추정 월 100회 | 여유를 둔 값 |
| 가구당 활성 사용자 수 | 1.0 vs 2.0 | CPU를 2배 가른다 |
| 주당 사람 개입 시간 | — | 10만 명 외삽 시 주 1.5시간 이하인가 |

### 함께 재는 가설

| # | 가설 | 방법 |
|---|---|---|
| A2-a | 과자는 위시리스트에 안 담긴다 | 담긴 물건 분류 분포 |
| A2-b | 지속재에 하루 대기가 견딜 만하다 | 종류별 완주율·우회율 |
| A2-c | 하루가 최적인가 | 12·24·48시간 A/B |
| A2-d | 목표 상상 문구가 취소율을 올리나 | 문구 유무 A/B (근거가 엇갈린 항목) |
| A3 | 6~9세가 두 칸 나누기를 스스로 한다 | 아이 단독 실행 비율 |
| A4 | 도안만으로도 실물 지갑과 실행률 차이가 크지 않다 | 도안 집단 vs 시판 지갑 집단 |

## G3 통과 조건 (이 POC 기준)

1. Phase 0 4주 지속률 50% 이상 → Phase 1 착수
2. 12주 안에 1인으로 Phase 2까지 도달. 초과했다면 사유와 남은 범위를 문서에
3. **실측 온보딩 통과율 × M1 활성률이 중간 시나리오(12%) 이상** — 미달이면 필요 다운로드가 카테고리 천장을 넘으므로 **종료**
4. 실측 CPU_월이 추정(6원)의 2배 이내
5. 실측 운영 부하를 10만 명으로 외삽해 주 1.5시간 이하, 또는 자동화 항목 특정
6. 인터뷰 5건 이상(이탈자 2건 포함)에서 반증된 가정이 있으면 브리프 갱신

> 인터뷰는 **POC 뒤에** 한다. 쓸 물건이 없는 상태의 인터뷰는 의견을 모으지만, 써 본 사람의 인터뷰는 행동을 확인한다.
